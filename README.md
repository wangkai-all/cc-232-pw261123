# 图书发行数据分析(本地工具 · 虚构数据)

把**发货、渠道实销、退书、库存与版次关系**放在同一个页面里分析的本地 Web 工具。
纯静态页面 + 程序生成的虚构数据, 不联网、不对接任何出版社或渠道接口。

## 运行

```bash
# 方式一: 直接双击打开
web/index.html

# 方式二: 本地服务(推荐)
python3 -m http.server 8000 --directory web
# 浏览器打开 http://localhost:8000
```

无需安装任何前端依赖。

## 页面

| 页签 | 内容 |
|---|---|
| 总览 | 发货/实销/退书/渠道在库/社内库存 KPI, 月度趋势, 渠道压货排行, 未到观察期批次提醒 |
| 图书明细 | 一本书各版本(ISBN)的流量 tiles、**各渠道去向**(实销/已退/在库)、批次与退书窗口、该版本修订记录 |
| 版次对比 | 同一作品各版次/装帧并排对比, 累计动销率按版龄对齐; 不同装帧是独立 ISBN, 全程分别统计不合并 |
| 退书情景 | 可调参数(观察窗口、退书率分位、估算方式、最小样本)的在窗批次退书演算, **预计差额来源可逐层展开** |
| 修订记录 | 迟到实销/退书修订台账, 首次值与修订值前后版本均保留 |
| 数据导出 | 发货/实销/退书/流向汇总/情景估算/修订台账 CSV 与整包 JSON |

顶栏「计入迟到修订」开关在**修订链最新值**与**首次上报值**两种口径间切换全部视图。

## 口径约定

- **发到渠道 ≠ 卖给读者**: 发货只说明书到了渠道; 实销是渠道上报真正卖给读者的量;
  渠道在库(压货) = 发货 − 实销 − 退书, 是退书压力的来源。
- **版次关系**: 再版换 ISBN 时保留版本对应(接替链), 同一作品可同时存在多个在版 ISBN;
  不同装帧(精装/平装)是不同 ISBN, 任何视图都不合并。
- **退货分摊**: 渠道退货按发货先后(FIFO)分摊到批次, 用于计算批次退货率。
- **退书窗口**: 每个发货批次有约定窗口(月); 窗口未关闭的批次**单独标识**,
  其最终退货未知, 只参与情景估算。
- **退书情景**: 用已出窗的**历史同类批次**退书率(同类·同渠道 → 同类·同渠道类型 →
  同类 → 同渠道类型 → 全部, 样本不足逐层回退)乘以可调分位取值, 演算在窗批次
  「还需退回多少」。**情景值是假设演算, 不是确定预测, 不写入实际退书数据**;
  导出的估算文件每行都标注「情景估算-非实际数据」。
- **修订**: 迟到实销与退书清点修订以修订链存储, 前后版本都保留, 互不覆盖。

## 目录

```
web/            静态页面(index.html / app.js / scenario.js / styles.css / data.js)
tools/generate_data.py   虚构数据生成器(固定种子, 可复现)
tools/test_scenario.js   对账与情景引擎测试: node tools/test_scenario.js
tools/smoke_dom.js       页面渲染冒烟测试(需 jsdom): node tools/smoke_dom.js
data/dataset.json        同一份虚构数据的 JSON 副本
```

## 重新生成数据 / 测试

```bash
python3 tools/generate_data.py   # 重新生成 web/data.js 与 data/dataset.json
node tools/test_scenario.js      # 对账约束、修订链、FIFO 分摊、情景引擎
node tools/smoke_dom.js          # jsdom 渲染冒烟(需自行 npm install jsdom)
```
